Replacing the WordPress site on pulsefulfilment.co.uk

Plan for switching pulsefulfilment.co.uk from the current WordPress/Elementor build to the new static HTML site, hosted on Ionos, with 301 redirects so no existing URL breaks and search rankings carry over.

Prepared15 September 2026
Current siteWordPress / Elementor on Ionos
New siteStatic HTML (deploy-couk/ package)
Domain after switchhttps://pulsefulfilment.co.uk

01Summary

The new site is a full rebuild with a different structure, so this is a re-platform rather than a file swap. Every URL in the live sitemap (78 pages, 1 blog post, 1 archive) has been mapped to a destination on the new site. All mappings are captured in the attached Migration URL Map.csv and implemented as Apache rewrite rules in the .htaccess file inside the deploy package.

02Decisions still open

1. Seventeen live integration pages have no page on the new site (see 04). They currently redirect to the /integrations hub. Five are carriers (Royal Mail, DHL, FedEx, APC, The Pallet Network). Check Search Console for organic traffic; anything that ranks or drives enquiries should get a page on the new site instead of a redirect.
2. Twelve sector landing pages collapse into one /sectors page. These are indexed landing pages that may rank for their own keywords. Same test: check traffic before accepting the consolidation.
3. Forms. The Contact and Get pricing forms currently have no back end. They need a static-friendly endpoint (Ionos form mailer, Formspree, or CRM embed) wired in and tested before launch.

03Deploy package

The folder deploy-couk/ is ready to upload. It contains:

  • All 41 pages as folder/index.html, giving clean extensionless URLs with no rewrite needed.
  • Every pulsefulfilment.com reference (canonical, og:url, JSON-LD, sitemap, robots — 416 in total) already changed to pulsefulfilment.co.uk.
  • .htaccess — https + non-www canonical host, 75 exact 301 rules, pattern rules for WordPress date/category/author archives, trailing-slash normalisation, 410 Gone for wp-admin, wp-login.php, xmlrpc.php, cache headers.
  • 404.html — branded not-found page (referenced by ErrorDocument).
  • sitemap.xml and robots.txt pointing at the .co.uk domain.

Extract of the redirect rules, to show the pattern:

RewriteCond %{HTTPS} !=on [OR]
RewriteCond %{HTTP_HOST} ^www\. [NC]
RewriteRule ^ https://pulsefulfilment.co.uk%{REQUEST_URI} [R=301,L,NE]

RewriteRule ^contact\-us/?$ /contact [R=301,L]
RewriteRule ^platinum/?$ /pricing [R=301,L]
RewriteRule ^beauty\-cosmetics\-fulfilment/?$ /sectors [R=301,L]
RewriteRule ^woo\-commerce/?$ /integrations/woocommerce [R=301,L]
RewriteRule ^(category|tag|author)(/.*)?$ /blog [R=301,L]

05Cutover steps on Ionos

  1. Back up WordPress. Files and database via the Ionos hosting panel. Keep for at least 30 days.
  2. Lower DNS TTL. Set the .co.uk A record TTL to 300s the day before, so any rollback is fast. Do not change MX records — email stays as is.
  3. Wire up forms (decision 3) and test a real submission.
  4. Stage first. Upload deploy-couk/ to a subfolder or temporary subdomain via SFTP. Click through every page. Run the URL map against it: every live URL should return 301 → 200.
  5. Swap the webroot. Rename the WordPress directory (keep it). Move the contents of deploy-couk/ into the domain's document root, including the hidden .htaccess. Remove the old WordPress .htaccess so the two do not conflict.
  6. Confirm SSL. Same domain, so the existing Ionos certificate should carry over. Check https loads and http redirects.
  7. Search Console. Submit https://pulsefulfilment.co.uk/sitemap.xml, request indexing of the homepage, monitor the Pages report for 404s for six weeks.
  8. Decommission. After 30 clean days, delete the renamed WordPress directory and database, and cancel WordPress plugin licences.

06Rollback

If anything is wrong after the swap, rename the directories back and restore the WordPress .htaccess. With the low TTL and no DNS change, the site reverts within minutes.
